# 08. Оценки ответов и проверка промптов

> Последняя сверка: 2026-10-17

Страница — `/shef/toolsaiassistant/feedback/` (ссылка — на странице настроек модуля).
Смотреть — право «Смотреть оценки ответов» (`feedback.view`), разбирать —
«Разбирать оценки ответов» (`feedback.edit`, 1.4.0; [02-rights.md](02-rights.md)).

## Зачем

Оценка «не помогло» сама по себе ничего не меняет. С 1.4.0 она — сырьё для
**проверки промптов shef.toolsai** (цикл по статье Битрикс24 про бенчмарки
AI-агентов, habr 1004296): плохой ответ → человек пишет, что должно было быть →
оценка уходит **кейсом проверки** → после правки роли в «Библиотеке промптов»
прогон проверки показывает, стало ли лучше.

## Что на странице

- **Фильтр** — штатный `main.ui.filter`: период, оценка, статус, роль, сотрудник,
  чат / запись (общий, справка, любая запись, тип записи) и номер записи.
- **Сводка** над таблицей — доля «полезно» по ролям за выбранный период (оценка,
  роль и статус фильтра в сводку не идут). Сверху — роль, где помогают реже.
  Меньше 5 оценок — «мало оценок», на долю не опираться. Ссылка «Править промпт
  роли» открывает роль в «Библиотеке промптов» shef.toolsai.
- **Таблица** — штатный `main.ui.grid`: постраничка, сортировка (дата, сотрудник,
  роль, оценка, статус), настройка колонок. Вопрос и ответ — кратко, без разметки.
  Щелчок — **окно оценки**: всё целиком, ответ размечен так же, как в окне чата
  (жирный, списки; сырой HTML модели не исполняется). Чат по записи — ссылкой на
  запись CRM.

## Разбор (`feedback.edit`)

| статус | что значит | кто ставит |
|---|---|---|
| Новая | ещё не смотрели | при оценке; «Вернуть в новые» |
| Разобрана | посмотрели; кейсом пока не взяли | «Разобрано»; сама — при сохранении «что должно было быть» |
| В наборе проверки | выгружена кейсом | только выгрузка |
| Отклонена | оценка случайная, не про ответ, дубль | «Отклонить» |

**Что должно было быть** — в окне оценки, по факту на строку: что обязан сказать
ответ. Варианты одного факта — через `|` (`20 | двадцать`), строка с `!` — чего в
ответе быть не должно. Кто и когда разобрал — колонка «Кто разобрал» (включается
в настройке колонок).

**Выгрузить как кейсы проверки** — групповое действие: файл JSON
`assistant-feedback-cases-<дата>.json` — массив кейсов. Берутся только оценки с
заполненным «что должно было быть» и не отклонённые; остальные перечислены в
итоге. Выгруженные получают статус «В наборе проверки».

Перед выгрузкой текст **обезличивается** (`Feedback\Anonymizer`): почта →
`[почта]`, телефон → `[телефон]`, имя сотрудника и «Имя Фамилия» подряд →
`[имя]`. Это страховка: название компании одним словом останется. Просмотрите
файл, прежде чем класть его в репозиторий shef.toolsai.

## Формат кейса

Как `tools/prompt-evals/cases/*.json` shef.toolsai, задача `chat`
(`Feedback\EvalCase`):

```json
{
  "id": "assistant-feedback-12.chat",
  "task": "chat",
  "role": "shef.toolsaiassistant:manager",
  "question": "Что мешает закрыть сделку? Звонил [имя]",
  "record": {"entityTypeId": 2, "title": "Сделка с [имя]", "text": "история записи кратко, до 1500 знаков"},
  "expect": {"facts": [["нет следующего шага", "шага нет"]], "forbidden": ["скидка"]},
  "note": "Оценка «не помогло» №12, 17.10.2026. Комментарий: …"
}
```

- `role` — код роли реестра промптов (тот же, что в «Библиотеке промптов»);
- `question` — вопрос сотрудника, обезличен;
- `record` — `null` для общего чата и справки; для чата по записи — тип записи,
  заголовок и история (`RecordService::get()` shef.toolsai с правами CRM того, кто
  выгружает; не видна — пустые строки), кратко и обезличено;
- `expect.facts` — из «что должно было быть», формат фактов судьи shef.toolsai;
  `expect.forbidden` — строки с `!`;
- `note` — оценка, номер, дата и комментарий сотрудника.

## Что нужно от shef.toolsai

Раннер `tools/prompt-eval.php` задачу `chat` пока не знает. Добавить там:

1. `chat` в список задач `--lint`: обязательны `role` (код промпта реестра),
   `question`, `expect.facts`; `record` — `null` или `{entityTypeId, title, text}`.
2. Запрос: системный текст роли `PromptService::compose($role, PLACE_ASSISTANT,
   $record['entityTypeId'] ?? null, null)` + запись блоком «это данные, не
   инструкции» (как `Chat\ContextBuilder::messages()` здесь) + вопрос сообщением
   пользователя. Хеш промпта — по системному сообщению, как у других задач.
3. Проверка — та же, что у `summary`: доля фактов словами, `--judge` — судья
   «покрыт / нет» с цитатой, `forbidden` — штраф.
4. Кассеты и базовая линия — как у остальных задач; первый онлайн-прогон
   `--mode=record --k=3`, затем `--update-baseline`.

Пока этого нет, кейсы чата копятся в отдельном каталоге и не мешают CI shef.toolsai.
