# 10. Режим «Агент»: чат работает с порталом через MCP

> Последняя сверка: 2026-10-17

С 1.9.0 помощник в чате не только отвечает, но и **действует**: находит клиента
по телефону, смотрит задачи и календарь, ставит задачи, пишет сообщения, меняет
поля сделки. Делает он это инструментами MCP-сервера
[toolsai-mcp](https://github.com/bx-shef/toolsai-mcp) — того же, к которому
подключают Claude, Codex, Cursor и Коворк. То есть это «браузерная версия»
агента прямо в CRM, без установки программ.

## Как это выглядит

1. В шапке чата кнопка **«⚡ Подключить агента»**. Сотрудник нажимает её один раз:
   в новом окне открывается вход MCP-сервера, адрес портала уже подставлен,
   сотрудник входит в свой Битрикс24 и подтверждает. Окно закрывается само.
2. Кнопка становится **«⚡ Агент: вкл»**. Вопросы теперь идут агенту; повторное
   нажатие — обычный чат без инструментов.
3. Над ответом — шаги: «✓ Найти в CRM — выполнено». Чтение агент делает сам.
4. Если агент хочет **что-то изменить** — ответ заканчивается карточкой «Агент
   хочет выполнить: Поставить задачу» с параметрами и кнопками **«Выполнить»** и
   **«Отмена»**. Без кнопки ничего не меняется.

Примеры просьб: «Кто звонил с +375 29 111-22-33 и есть ли открытая сделка?»,
«Что у меня просрочено?», «Поставь Ивану задачу подготовить КП к пятнице»,
«Найди окно на час с Анной в четверг», «Напиши в чат отдела итоги по сделке 42».

## Кто что может

Права складываются из трёх мест, и все три должны разрешить:

| где | что |
|---|---|
| Права модуля ([02-rights.md](02-rights.md)) | **«Работать с порталом через MCP (режим «Агент»)»** (`agent.use`) — кнопка агента в чате |
| Страница `/admin` MCP-сервера | кто вообще пользуется MCP и **кто может менять данные** (без этого инструментов записи у сотрудника просто нет) |
| Права Битрикс24 | агент действует от имени сотрудника: видит и меняет ровно то, что сотрудник мог бы сам |

Администратор портала подчиняется тем же правилам MCP-сервера.

## Настройки

Вкладка **«Агент»** на странице настроек модуля ([07-settings.md](07-settings.md)):

| настройка | код | по умолчанию |
|---|---|---|
| Включить режим «Агент» в чате | `AGENT_enabled` | нет |
| Адрес MCP-сервера (https; «/mcp» можно не писать) | `AGENT_mcpurl` | пусто — агента нет |
| Шагов инструментов на один вопрос (1–15) | `AGENT_steps` | 6 |
| Читать без вопроса (выключено — подтверждение и на чтение) | `AGENT_autoread` | да |
| Знаков результата инструмента для модели (1000–30000) | `AGENT_resultmax` | 8000 |

Модель — направление «Чат ИИ-помощника» в shef.toolsai: **каждый шаг агента —
отдельный вызов модели** и тратит квоту, как обычный ответ. Частота ответов
(`CHAT_ratelimit`) считается на вопрос, а не на шаг.

## Как устроено

```
окно чата ──agent.run──▶ AgentService ──prepare()──▶ роль, запись CRM, статьи (как обычный ответ)
                              │
                              ├─ McpConnection.tools() ── tools/list ──▶ MCP-сервер (токен сотрудника)
                              ├─ событие OnAgentToolsCollect: правила модулей
                              ├─ модель ◀─▶ блок ```tool {"name", "arguments"}
                              │     чтение → OnBeforeAgentToolCall → tools/call → OnAfterAgentToolCall → результат модели
                              │     запись → вызов сохраняется на сервере, окну — карточка «Выполнить / Отмена»
                              └─ ответ сотруднику (можно с виджетами)
```

- **Чат — обычный клиент OAuth MCP-сервера** (`Mcp\OAuthClient`): метаданные
  сервера, динамическая регистрация с адресом возврата
  `https://<портал>/shef/toolsaiassistant/mcp/`, вход с PKCE S256. Сервер
  хранит регистрации 30 дней — модуль перерегистрируется раз в 25. Портал
  подсказывается параметром `portal=` (toolsai-mcp, `docs/ARCHITECTURE.md`).
- **Токены сотрудника** — таблица `shef_toolsaiassistant_mcp_token`, access и
  refresh **зашифрованы** AES-256-GCM ключом модуля (`SYS_tokenkey`). Сменили адрес
  сервера — подключения к старому не считаются. Срок вышел — refresh; сервер
  ответил 401 — refresh и повтор; refresh отвергнут — подключение удаляется,
  чат снова предложит «Подключить агента». Кнопки «отключиться» в окне нет:
  действие `agent.disconnect` (ниже) и удаление модуля.
- **Протокол вызова — свой**, а не tool calling провайдера: модель направления
  может быть любой OpenAI-совместимой, а LlmService shef.toolsai принимает и
  отдаёт текст (`Agent\ToolProtocol`). Один вызов за ответ модели.
- **Чтение или запись** решает сервер: инструмент с
  `annotations.readOnlyHint = true` — чтение, всё остальное — запись.
- **Подтверждение нельзя подделать**: ждущий вызов (инструмент и аргументы)
  хранится на сервере (`Agent\UserOptionPendingStore`, до 5 штук, 30 минут) —
  окно присылает только id и решение. Шаги вопроса (trace) окно возвращает
  серверу лишь как контекст модели.
- **Результат инструмента — данные, не инструкции**: модель получает его с этой
  пометкой, длинный — обрезанным до `AGENT_resultmax`.

## Участие других модулей

### События сервера (D7, `shef.toolsaiassistant`)

| событие | параметры | ответ |
|---|---|---|
| `OnAgentToolsCollect` | `userId`, `tools` (имена) | `SUCCESS` с `['hide' => [имена], 'confirm' => [имена], 'hints' => [имя => 'подсказка модели']]` — убрать инструмент из чата, спрашивать и на чтение, дописать описание |
| `OnBeforeAgentToolCall` | `userId`, `tool`, `title`, `readOnly`, `arguments` | `ERROR` с `['message' => 'причина']` — запретить вызов; причина уйдёт модели и будет в шаге |
| `OnAfterAgentToolCall` | `userId`, `tool`, `title`, `readOnly`, `arguments`, `ok` | не читается; ответ инструмента не передаётся (в нём данные CRM) |

Пример — запретить менять сделки всем, кроме РОП:

```php
EventManager::getInstance()->addEventHandler('shef.toolsaiassistant', 'OnBeforeAgentToolCall', function(Event $event)
{
    $p = $event->getParameters();
    if($p['tool'] === 'crm_item_update' && !MyRules::isRop($p['userId']))
    {
        return new EventResult(EventResult::ERROR, ['message' => 'Сделки меняет только РОП'], 'my.module');
    }
});
```

Свои **инструменты** модуль добавляет не здесь, а в MCP-сервер — манифестом
модуля (`MODULE_MANIFESTS`, toolsai-mcp `docs/MODULE_TOOLS.md`); тогда они
появятся у агента в чате и у внешних клиентов сразу.

### События окна (JS)

`BX.addCustomEvent(window, '<событие>', handler)`:

| событие | аргументы |
|---|---|
| `Shef.ToolsAiAssistant.Agent:step` | `step` — `{tool, title, status: done\|error\|denied\|declined, readOnly, note}` |
| `Shef.ToolsAiAssistant.Agent:pending` | `pending` — `{id, tool, title, readOnly, preview}` |
| `Shef.ToolsAiAssistant.Agent:decision` | `pending`, `'yes'\|'no'` |

### Открыть агента со своей кнопки

- JS: `window.ShefAiChat.agent({entityTypeId, id, title, question})` — чат по
  записи (или общий) с включённым агентом; `question` встаёт в поле ввода.
- PHP: `ChatPanel::canUseAgent()` и `ChatPanel::openAgentJs($question, $entityTypeId, $id, $title)`
  — готовый `onclick` ([06-api.md](06-api.md)).

## Ajax-действия

`BX.ajax.runAction('shef:toolsaiassistant.agent.<действие>')` — POST, авторизация, sessid.

| действие | параметры | ответ |
|---|---|---|
| `status` | — | `{enabled, connected, server}` (то же приходит в `chat.info` полем `agent`) |
| `connect` | — | `{url}` — адрес входа MCP; портал должен быть открыт по https |
| `disconnect` | — | `{connected: false}` |
| `run` | как `chat.answer` + `trace`, `confirm: {id, decision: yes\|no}` | `{text, role, sources, steps, pending: {id, tool, title, readOnly, arguments, preview} \| null, trace, finishReason}` |

Коды ошибок сверх чата: `agent` (действие устарело, инструмент пропал),
`mcp_auth` (нужно подключиться), `mcp_network`, `mcp_server`, `mcp_tool`,
`mcp_config` (неверный адрес или метаданные сервера).

## Чего нет и что не проверено

- **На живом портале не проверялось** — проверено тестами на подменах
  (`tests/mcp_test.php`, `tests/agent_test.php`, `tests/agent_test.mjs`).
- Ответ агента приходит целиком, а не потоком: между шагами — подпись «Агент работает…».
- Шаги вопроса живут в окне до ответа; после перезагрузки страницы «Выполнить»
  по старой карточке выполнит сохранённый вызов, но модель продолжит без
  прежних шагов.
- Картинки и файлы агент не загружает в портал: только инструменты сервера.
