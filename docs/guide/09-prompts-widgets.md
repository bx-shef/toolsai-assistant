# 09. Меню промптов и виджеты в ответах

> Последняя сверка: 2026-10-17

С версии 1.7.0. Нужен shef.toolsai 1.59.0 (`PromptService::skills()`); со старым
shef.toolsai меню промптов не появляется, виджеты работают.

## Меню промптов

Кнопка ✦ слева от поля ввода или «/» в пустом поле — меню, как у задач Битрикс24:

* **сверху — роль** помощника, клик — «Выбрать роль»;
* **Избранные** — промпты, отмеченные сотрудником в библиотеке;
* **Для этой записи** — чат открыт из карточки CRM;
* **Для списка** — чат открыт на странице списка CRM без записи;
* **Общие** — везде;
* внизу — ссылка **«Библиотека промптов»** shef.toolsai (`/shef/toolsai/?section=promptlib`).

Поиск — по названию и тексту. Промпт «с уточнениями» (`type = template`) встаёт в поле
ввода, первое `[ … ]` выделено, Tab — к следующему. Обычный — отправляется сразу.

**Откуда промпты.** Навыки библиотеки промптов shef.toolsai с местами чата —
«Чат помощника: везде», «…: список CRM», «…: карточка записи». Модуль кладёт туда
десять типовых запросов (`Prompt\TypicalPrompts`): кратко о записи и следующий шаг,
риски сделки, что обещали клиенту, письмо клиенту, подготовка к звонку; что застряло,
кому позвонить сегодня, сводка по воронке; объясни, перепиши понятнее. Администратор
правит и выключает их в «Библиотеке промптов» и добавляет свои — с нужным местом в
«Где доступен». Навык роли показывается только с этой ролью, общий — со всеми.
«Кому доступна», скрытые сотрудником и избранные — как в библиотеке.

Устройство: места окна — `Prompt\ChatPlaces::forWindow()` (запись — карточка, вид
`list` — список, справка — без меню), список — `ToolsAiPromptSource::prompts()` →
`PromptService::skills()`, группы и поиск — `promptmenu.js` (`tests/promptmenu_test.mjs`).

## Виджеты в ответах

Когда цифры, сравнение или следующий шаг нагляднее показать, модель вставляет в ответ
блок

    ```widget
    {"type": "kpi", "items": [{"label": "Сделок в работе", "value": 12}]}
    ```

и окно рисует карточку вместо кода. О виджетах модель знает из системного текста
(`Chat\WidgetCatalog::instructions()`, после текста роли).

| тип | данные |
|---|---|
| `kpi` | плитки показателей: `items: [{label, value, hint, trend: up/down}]`, до 8 |
| `table` | таблица: `columns`, `rows`, до 12 столбцов и 50 строк |
| `bars` | полосы — простой график: `items: [{label, value}]`, `unit` |
| `record` | карточка записи CRM со ссылкой: `entityTypeId`, `id`, `title`, `subtitle`, `stage`, `fields` |
| `actions` | кнопки следующего шага: `items: [{label, prompt, send}]` — вставить запрос в поле или отправить |

У любого виджета может быть `title`.

**Безопасность.** Всё, что прислала модель, — данные: виджеты рисуют узлы с
`textContent`, без `innerHTML`; ссылка — только на карточку записи своего портала
(`/crm/…/details/<ID>/`), открывается слайдером. Негодный JSON — обычный блок кода,
неизвестный тип или сбой рисования — подпись «Виджет недоступен». Пока ответ
печатается, на месте блока — «Готовлю виджет…».

### Свой виджет из другого модуля

Два шага — JS рисует, PHP рассказывает модели:

1. В своём JS-расширении зарегистрировать тип:

   ```js
   BX.Shef.ToolsAiAssistant.Widgets.register('my.module:weather', {
       render: function(data, ctx) {
           var box = ctx.el('div', 'my-weather');
           box.appendChild(ctx.el('b', '', data.city));
           return box; // узел; строку HTML не вставляем
       }
   });
   ```

   `ctx`: `el(tag, cls, text)`, `prefill(text)`, `send(text)`, `recordUrl(entityTypeId, id)`.

2. Обработчиком `shef.toolsaiassistant:OnChatWidgetsCollect` сообщить тип, расширение
   и описание данных для модели:

   ```php
   return new EventResult(EventResult::SUCCESS, ['widgets' => [[
       'type' => 'weather',
       'extension' => 'my.module.chat-widgets',
       'description' => 'Погода: {"city": "…", "temp": число}',
   ]]], 'my.module');
   ```

Тип хранится как `<модуль>:<тип>` — с чужими не пересекается. Окно подключает
расширение (`BX.Runtime.loadExtension`) и перерисовывает ответы. Модулей — до 20 типов.

Устройство: разбор блока — `markdown.js` (`renderFull`, `tests/markdown_test.mjs`),
реестр и встроенные — `widgets.js` (`tests/widgets_test.mjs`), каталог и подсказка —
`Chat\WidgetCatalog` (`tests/prompts_test.php`).

## Файлы в чате

Сотрудник прикладывает до 5 файлов к вопросу — скрепкой у поля ввода или
перетаскиванием в окно: «сравни два КП», «что в договоре про штрафы», «какие
товары подорожали в новом прайсе».

| вид | как читается |
|---|---|
| PDF | текстовый слой штатным `ui.pdfjs` ядра, строки по координатам |
| DOCX, PPTX | текст абзацев и слайдов, таблицы — строками через «\|» |
| XLSX | листы строками, ячейки через «\|» |
| CSV, TXT | как есть, UTF-8 или windows-1251 |

Файл разбирается в браузере и на портал не загружается; на сервер уходит только
текст, тот же, что сотрудник мог бы вставить руками. Пределы: 30 000 знаков с
файла, 60 000 на всю переписку (свежие файлы важнее), длинный файл показывается
началом с пометкой. Картинки и сканы без текста не читаются: модель текстовая.
