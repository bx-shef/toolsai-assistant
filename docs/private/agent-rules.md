# Правила агента

> Последняя сверка: 2026-10-17

Правила процесса — **те же, что у shef.toolsai**:
[docs/private/agent-rules.md shef.toolsai](https://github.com/bx-shef/toolsai/blob/main/docs/private/agent-rules.md).
При расхождении прав тот документ; ниже — выжимка и то, что отличается здесь.

1. **Источники.** API Битрикса — по документации (`.bitrix-docs/framework-docs`,
   в `.gitignore`) и коду ядра портала; расхождение — прав код ядра, отметить в PR.
   Классы и методы не выдумывать.
2. **Путь до `main`** — только через PR; ветка, `./build.sh --check`, CI зелёный.
3. **Ревью** — навык `review-panel`: `/code-review` всегда; панель из пяти
   (документация, инженер, QA, безопасность, CTO) — на поведение, права, деньги,
   установщик, CI.
4. **Документация** — в том же PR, что код; штамп «Последняя сверка».
5. **Дисциплина** — замер вместо «должно»; исправленный гард — с тестом, который
   краснеет; никогда `git checkout --` поверх чужой правки.
6. **shef.toolsai не правим отсюда.** Не хватает публичного API — требование в
   [guide/03-dependencies.md](../guide/03-dependencies.md) и issue в shef.toolsai.
7. **Решает владелец**: новые зависимости, права по умолчанию, тексты ролей по
   умолчанию, мерж.
8. **Выпуск с новой версией — тег.** После мержа PR, который поднял `VERSION` в `install/version.php`, ставим аннотированный тег `v<версия>` на squash-коммит в `main`: `git tag -a v<версия> -m "<заголовок squash-коммита>" <коммит>`, затем `git push origin v<версия>`. Тег с такой версией уже есть — не перезаписываем. Решение владельца от 2026-10-17.
