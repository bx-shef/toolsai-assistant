# Ревью PR: `/code-review` и панель из пяти

> Последняя сверка: 2026-10-04

Правила — [docs/private/agent-rules.md](../../../docs/private/agent-rules.md), §3. Этот навык —
порядок действий. Расходятся — прав agent-rules, а навык правится в том же PR.

## 1. Подготовка

1. `git fetch origin main && git merge origin/main` в ветку PR — проверяем то,
   во что PR вольётся. Чужую ветку не перебазируем.
2. Написать **простыми словами**, что PR делает и зачем, в 3–6 строк. Не
   пишется коротко — PR делает слишком много, сказать об этом.
3. `./build.sh --check` — зелёный. Ровно это гоняет CI.

## 2. Кого звать

`/code-review` по дифу — **всегда**.

Панель из пяти — по таблице agent-rules §3.2. Коротко: меняется поведение
модуля, публичный API `Shef\ToolsAi\…`, схема таблиц, коды настроек, эндпоинт,
квота и расход, установщик, сборка, релиз, CI — или правка выросла из
рассуждения, а не из замера. Сомневаешься — зови.

## 3. Панель — пять агентов одним сообщением, параллельно

| роль | смотрит |
|---|---|
| **Документация** | `docs/`, `CLAUDE.md`, `README.md`, `CHANGELOG.md`, навыки, примеры: верно ли против кода, сверена ли документация с правкой (agent-rules §4.1), открываются ли ссылки, сходятся ли `файл:строка` ядра |
| **Инженер** | верность решений; канон линейки (`lib/` строчными, установщик, `strict_types`, раскладка); опоры на ядро — с `файл:строка` из [00-research.md](../../../docs/private/00-research.md); типы и докблоки |
| **QA** | краснеет ли тест, если сломать код; всё ли заявленное в PR проверено; что можно проверить только на стенде — так ли и названо |
| **Безопасность** | эндпоинт (токен, колбэк, SSRF), страницы в `/bitrix/admin` (права, XSS, CSRF), секреты в логах, ошибках и отчётах, SQL, данные клиента в публичном репозитории |
| **CTO** | изменение целиком: объём, цена, направление, что оно обещает линейке и порталу клиента; не решение ли это владельца (agent-rules §5.8) |

Каждому в задании — дословно по смыслу:

- Проект большой. Начни с `git diff origin/main...HEAD --stat`, читай по делу,
  не грузи всё дерево, не упади по таймауту.
- Дерево общее. Чужая правка — сосед, не откатывать и не строить на ней теорий.
- Код меняет только QA и только чтобы проверить, что тест краснеет, — в
  отдельном `git worktree`. Откат мутации — из копии в `/tmp` или scratchpad,
  **никогда** `git checkout --`.
- Ядро Битрикса и REST сверять с источником (agent-rules §1), не по памяти.
- Сообщать находки: файл:строка, что, почему важно, как чинить, насколько
  уверен. Не чинить.

## 4. Отчёт владельцу — по-русски, коротко

Блок на проверяющего: **кто — что — почему важно — как чинить**. Без
стенограмм. Отдельно — что берёшь в работу и что нет, с причиной и замером.

## 5. Исправления

- Всё — **в этом же PR**. Просится в отдельный issue или PR — не выносить
  молча, сказать и обсудить.
- Исправленный гард — с тестом, который краснеет при мутации (agent-rules §5.2).
- После правок: `./build.sh --check`, пуш. Переделка существенная — панель
  заново.
